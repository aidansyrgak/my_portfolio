Hospital Application

Hospital Navigation and Service Request Application

Software engineering project in collaboration with Brigham & Women’s Hospital. This project had ten-person student teams working in a competition to apply Agile development methodologies and software design patterns in Java to prototype a hospital operations application. The application focused on map-based navigation and service requests. It was then presented to the hospital dev team for potential features, UI concepts, and design directions for future development.

Features:

  • Interactive path-finding map, implemented with the A* algorithm, to guide users through hospital spaces.
  • Messaging system for communication between users and staff.
  • Service request modules for common hospital operations and maintenance.
  • Facilities move workflows to support office and department relocations.
  • Tech stack: Java, JavaFX, MaterialFX, AWS, PostgreSQL, Hibernate.

Cache Simulator

Cache Simulator

This tool explores how CPU cache parameters can be inferred using only memory access behavior, without inspecting internal cache state. I built a DineroIV-style cache simulator and a trace-driven analyzer that generates targeted memory reference streams and interprets aggregate hit/miss results to deduce cache info (block size, capacity, associativity, replacement policy). The analyzer uses black-box testing to infer cache behavior from simulator output, mirroring real-world trace-based cache analysis. The project highlights both the power and the limitations of inference when multiple cache organizations exhibit equivalent observable behavior.

Features:

  • Configurable simulator that models CPU cache behavior across multiple architectures.
  • Supports direct-mapped, 2-way set associative, 4-way set associative, and column-associative configurations.
  • Column-assoicative cache implemented as described by Agarwal and Pudar in this paper.
  • Cache block size identification through spatial locality patterns.
  • Cache associativity inference using controlled set conflicts.
  • Replacement policy differentiation through ordered access patterns.
